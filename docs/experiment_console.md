# 本地实验操作台

真实本地GPU实验台运行在T640服务器上，只监听服务器自己的`127.0.0.1:8766`。Windows电脑与T640处于同一局域网（或已接入能访问T640的内网VPN）时，双击 **打开T640实验操作台.cmd**；脚本会在必要时启动服务器端实验台，再建立SSH端口转发。浏览器仍然打开 `http://127.0.0.1:8766`，但页面和实验命令实际由T640执行。

这条访问链路不需要公网IP、域名、ICP备案或向互联网开放端口。网页服务没有内建登录，因此不要把8766直接绑定到`0.0.0.0`；SSH负责身份认证和加密。关闭浏览器不会停止实验；关闭隐藏的SSH进程只会断开本机访问，也不会停止T640上的实验。

打开页面、生成清单、筛选或查看结果都不调用模型。只有点击 **开始所选run · 调用本地模型** 或 **继续未完成项** 才请求三张本地GPU。`scripts/Start-ExperimentConsole.ps1`和原 **启动实验操作台.cmd** 仍用于Windows本机的旧外部API模式，不会被误接到T640的回环GPU端点。

手动执行时，在T640保持操作台仅监听回环地址：

```bash
cd /home/evan/ai/staging/protocol-refactor-native-v2-20261101
PYTHONPATH="$PWD/src" PILOT01_EXECUTION_BACKEND=local-gpu \
PILOT01_GPU_MONITOR_MODE=local .venv/bin/python -m pilot01.experiment.console --port 8766
```

然后在Windows电脑执行：

```powershell
ssh -N -L 8766:127.0.0.1:8766 evan@<T640的内网IP>
```

浏览器访问`http://127.0.0.1:8766`。如果已经配置SSH别名`t640`，可用`evan@<T640的内网IP>`替换为`t640`。

## GPU 与推理服务监控

实验台首页已经合并只读GPU监控，不再需要另开模型监控面板。页面每5秒读取一次：

- GPU0、GPU1、GPU2的温度、功率/功率上限、计算利用率和显存；
- 最近120次采样的利用率与温度趋势；
- 热降频和不可纠正ECC状态；
- 三个SGLang端点的模型、工具解析器、最大并发以及可用时的运行/排队请求数。

Windows本地启动默认通过SSH别名`t640`只读采集；不会保存SSH私钥，也不会执行实验命令。直接在T640部署时设置`PILOT01_GPU_MONITOR_MODE=local`，云部署的systemd模板已经包含该设置。监控失败只会显示“监控离线”，不会启动、停止或影响实验。

## Agent 像素办公室

首页的像素办公室是同一份`/api/state`实时摘要的游戏化呈现，不是模拟结果。4条固定通道各配对一个Manager和一个Compliance工位；同一run在整段执行期间占用同一条通道。角色坐在地图内的桌前，而不是显示为状态卡片。实际并发超过4条通道时，额外run继续正常执行，并以“后台 +N”明确披露，不伪装成只有4个任务。

工作时的自言自语只由可审计字段派生：CASE、当前节点、请求阶段、已返回调用数、工具数和A/V/D/E条件。服务端把每个角色的`role_started_at`以及真实Manager→Compliance切换的`handoff_at`写入`console_activity.jsonl`并同步到`/api/state`。前端仅在检测到该真实切换时，才让对应Manager离座、沿中央通道走到配对Compliance工位并显示交接对话；旧事件不会在每次刷新时重复表演。它不读取、不展示也不猜测模型隐藏推理。点击有run的角色可打开正式记录；打开办公室、动画刷新和点击空闲工位都不会发起模型请求。

办公室地图是项目内原创像素素材`src/pilot01/experiment/assets/pixel-office-room-v2.png`，人物、显示器、行走和对话由本地CSS/JavaScript绘制；没有复用第三方游戏角色或贴图。窄屏使用可横向浏览的完整游戏地图，8个配对工位和交接路径不会被折叠掉。

## 实验台与实验记录

顶部导航可在“实验台”和“实验记录”之间切换。记录页地址为 `http://127.0.0.1:8766/records`。浏览历史记录不会切换当前实验、补跑旧run或启动模型调用；返回记录页会恢复上次选中的批次、run和回放位置。

- **读取历史批次**：SQLite摘要索引提供批次统计及每页100条run，支持按合同/run编号搜索和执行状态筛选；批次统计始终覆盖本批所选项，不随分页或筛选改变。选中单轮后才读取该轮的完整过程，展开原始文本时才渲染长内容。
- **上传CSV**：支持操作台导出的CSV，至少含run_id、case_id、status列。展示汇总；没有原始日志就不生成逐步过程、原文或条款恢复率。
- **完整ZIP记录包**：点击“导出完整记录ZIP”，每个run独立保存为`runs/<序号>/record.json`，包含输入、响应、工具、核验、结果、研究侧标注和已有注释。包内`manifest.json`保存批次信息和路径映射，重新上传后可回放。服务端使用临时文件逐轮打包，浏览器直接下载，不在内存中组装整批大JSON。
- **兼容旧JSON包**：仍可上传旧完整JSON包或单个run.json。旧包首次读取时会拆成独立单轮文件，保留旧包原件；之后点开单轮不再解析整个包。单个run.json通常不包含独立的模型调用日志。
- **上传原始日志ZIP**：压缩单个批次的raw目录，保留每run的独立文件夹。识别run.json、model_calls.jsonl、tool_calls.jsonl、verification.jsonl；可有多层外包装目录。只读取这些数据文件，不解压执行内容。一个ZIP只能含一个批次。

ZIP上传不超过512MB、展开后不超过2GB和100000个文件；单轮记录不超过128MB。CSV、旧JSON上传不超过64MB。每包最多10000条run。上传过程分块写入临时文件，ZIP逐轮校验和保存；全部通过后才发布导入批次。上传记录单独保存在 `outputs/experiment_console/imports/<随机ID>/`，保留`source.*`原件，刷新或重启后仍可读取，不覆盖历史实验。

索引保存在`outputs/experiment_console/index/records.sqlite3`。首次读取旧记录需要建立摘要索引，之后只同步变化的run；原始JSON/JSONL仍是证据，数据库可从它们重建。实时进度首次返回轻量摘要，后续按版本返回变化项；运行中每2秒、空闲时每10秒检查，旧版本游标或服务重启后自动退回完整摘要。HTTP重试统计只读取新追加的完整日志行。详细设计和重建命令见[记录索引说明](records_storage_v2.md)。

中文对白是对可见动作的转述，不表示记录了agent的内部思考。现有32轮已核对的中文解说与原始run文件SHA256绑定；其他记录按实际动作生成说明，原始提交理由保留供展开核对。缺失输入、未执行的下游或没有保存的工具返回会明确标注，不补写成已发生的行为。

历史强制拦截版本仍按当时中止事实展示，当前audit_only版本展示“检查未通过但继续”。读取本地标注前核对冻结计划的registry指纹；上传包内的标注和注释注明来自文件，不将其当作系统独立核实的结论。

## 第一次怎么用

1. 选择A/V/E/D条件和重复次数，生成固定计划。
2. 选择本轮实际要运行的run；完整计划与本轮子集分别保存。
3. “实验并发”默认4，可填1到12。它控制同时执行的完整run，不会改写模型服务自身参数。
4. 分别为Manager和Compliance勾选GPU0、GPU1、GPU2；每类角色至少一张卡。默认Manager使用GPU0，Compliance使用GPU1。
5. 展开“已锁定的模型与协议参数”，核对Qwen3.8-27B、native-v2、xhigh、温度、输出上限、16次工具预算等冻结值。
6. 点击“开始”。页面显示实际HTTP在途数、当前节点、GPU状态和完整记录。

## 当前接入的实验范围

操作台使用新材料中的**旧40份开发合同**，默认完整计划为72份memo × D0/D1/D2 =216项，每格1次。新40份没有被用于这次开发预试。

三组均允许查原文，均接受validator检查，仅检查规则的告知程度不同。最终A/V/D主实验矩阵尚未确认，本操作台当前安排的是D版本开发预试。

选择64项会保留完整216项计划，同时冻结这次选中的64个ID。未选中的152项不发请求，在完整计划的研究汇总中仍列为未启动。面板的进度分母是本轮所选64项；任意选取可能不构成完整的条件配对，不当作完整主实验比较。

## 并发与额度

本轮选择的实验并发写入该批次自己的`console_execution.yaml`，并直接成为Runner的`max_workers`和`max_parallel_runs`。因此网页将4改成8，确实会让最多8个完整run并行推进；这不是只改显示值。

GPU模型服务是另一层限制：GPU0、GPU1、GPU2各自固定`max_running_requests=4`。网页不会改写它。若选择三张不同GPU，服务器最多允许12个模型HTTP请求同时在途；如果Manager与Compliance共享同一张卡，两类节点共同使用该卡的4个槽。网页即使把实验并发设为12，单卡仍不会超过4。

每个run的Manager和Compliance会分别从其所选GPU池中确定性分配；同一角色在该run的所有搜索、打开和后续模型轮次中固定使用同一端点。分配结果保存在`execution_policy.json`和启动快照。当前本地native-v2执行不自动补发HTTP失败；模型答案错误、工具预算耗尽和协议失败也不会自动重跑。

本地操作台默认使用版本化的`experiment_native_tools_retrieval_bounded_v3.yaml`，不会改写历史32768-token配置、context-safe v1或context-compact v2。模型基础上限为16384；工具可用轮与最终回答上限均为16384，格式修复上限4096。每次发送前使用服务器上冻结的Qwen tokenizer估算当前完整消息和工具架构，在49152-token上下文中预留1024 token安全空间。若声明输出仍放不下，客户端会自动下调本次`max_tokens`；若连最低2048 token输出空间都没有，则记录明确的`context_budget_failure`并在本地终止，不发送HTTP请求。实际采用的`max_tokens`保存在模型调用记录；HTTP尝试审计仍只记录状态、时序和端点槽位，不复制请求正文。

新版还将检索历史与审计历史分开：工具日志、游标、摘录和完整结果继续原样存档；后续模型输入中的无新增搜索改写为短检索账本，保留调用序号、查询、目标标签、结果类型和候选段落ID。输入估计超过18000 tokens时，从最旧且模型已经看过的搜索开始压缩，目标降到12000；完整打开的段落永不压缩。规范化后相同的查询会被工具层拒绝并照常计入共享工具预算；连续3次搜索或翻页没有新增段落ID后，本节点不再暴露搜索和翻页工具，只允许打开已经搜索到的合法段落或提交最终答案。完整规则见[检索上下文压缩记录](retrieval_context_compaction_20261101.md)。

CASE-0077的实际跟踪显示，正确证据在第一次搜索首屏已经返回，但模型继续把一个查询翻到第5页，并重复打开同一段落。bounded v3因此将每个独立查询限制为最多2页，并拒绝同一节点重复打开同一段落；拒绝仍进入工具日志并消耗共享预算。该轮最终还暴露了“工具仍可用时提交最终答案只获得8192输出”的截断，因此v3把工具可用轮上限提高到16384，仍由本地上下文预算动态收缩。完整记录见[有界检索修复记录](retrieval_bounded_fix_20261101.md)。

## 状态怎么读

- **等待**：本轮已选，但尚未开始。
- **执行中**：已启动，显示当前Manager或Compliance；可能正在等待该API的请求名额。实际HTTP数单独显示。
- **完成**：流程交付完成，不等于答案正确。REVIEW也可能是完成后的正常决策。
- **失败**：执行、输出结构或预算等原因导致本run未正常交付；历史强制核验版本还包括检查拦截，详情保留当时原因。
- **中断**：留下部分记录，但没有最终run文件，需要显式继续。

“已报告token”只合计已返回响应中的usage，不是完整账单；未返回请求、未报告usage和某些失败HTTP尝试的消耗可能尚不可知。HTTP补发次数与模型调用数分别记录。

## 停止、刷新与继续

“停止派发”只停止新的run，已经开始的run会继续结束并保存。如果64项已经全部开始，按钮不会取消这64个请求。停止后可点击“继续未完成项”；已完成及已记录失败的run会跳过，中断尝试会移开保留再执行。

刷新网页会恢复当前批次。服务重新启动后会读取最近一批记录，原先运行中的批次显示为中断。源码或配置发生变化时，操作台会阻止混用版本，需要重启并创建新版计划。

## 文件在哪里

所有新批次独立保存于 `outputs/experiment_console/`：

- `manifests/<批次ID>/`：完整计划、所选run、API分配、并发设置、调度与HTTP尝试日志。
- `raw/<批次ID>/<runID>/`：每run的模型、工具、validator和最终结果。
- `processed/<批次ID>/`：完整计划分母下的评分与汇总。

网页“导出当前结果 CSV”导出本轮所选项的当前快照。测试记录另存于 `outputs/experiment_console_validation_20261018/`，合成测试不属于真实实验结果。
