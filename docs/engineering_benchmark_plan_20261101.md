# 本地推理工程实验计划（2026-11-01）

本文件记录第一阶段七层架构收口后的工程实验决定。工程实验用于选择部署参数，不改写既有研究运行，也不把性能探针混作新的研究结果。

## 固定工作负载

- 实际任务质量基线复用此前已经完成并保留原始记录的五条历史异常重跑，不重复调用模型来制造一套“相同实验”。
- 功率与并发比较使用相同的冻结输入、请求顺序、采样配置和计量代码；每个新工程运行使用独立 ID 和输出目录。
- BF16 + MTP、TP=1、49,152 上下文、parser、工具预算与七层配置保持不变，除正在研究的单一因素外不同时改动其他参数。

## 功率实验

GPU 2 的实机功率范围为 150–300 W。本轮只比较：

`200 W、225 W、250 W、275 W`

不测试 300 W。每档记录实际平均与峰值功率、任务墙钟时间、首 token 延迟、输出吞吐、温度、显存、完成状态和协议错误。200 W 是当前部署基线。

## 并发实验

本轮直接比较 `max_running_requests`：

`2、4、8、16`

当前并发 1 的既有运行作为参考基线，不作为新 sweep 档位。每一档必须通过启动后实机检查确认，不能只改配置文件。报告区分服务请求并发与实验 run 并发，并记录排队、P50/P95 延迟、总吞吐、KV/显存压力、OOM、超时、截断和协议失败。

当前服务报告约 79,418 个可用 token 槽，不能保证多个 49,152-token 请求同时达到各自最大长度；高并发档位允许排队，但不得把排队请求误报为同时运行。

## FP8 兼容性边界

用户原文中的“FB8”按 FP8 理解。GPU 为 NVIDIA A800 80GB PCIe，compute capability 8.0（Ampere）。Ampere 原生 Tensor Core 类型包含 BF16/FP16/TF32/INT8/INT4，但没有 Hopper 一代的原生 FP8 Tensor Core。因此：

- FP8 首先是兼容性探针，不预设一定提速；
- 必须记录实际 kernel/backend，禁止把静默回退称为 FP8 加速；
- 区分 FP8 权重量化、FP8 KV cache 与端到端 FP8，它们不是同一配置；
- 若当前 SGLang/backend 拒绝或回退，优先比较 W8A16/INT8 和已有 INT4 + MTP 路线；
- 所有低精度结果相对 BF16 比较工具协议稳定性、答案质量、显存、吞吐和功耗。

## 执行顺序

1. 推送当前 BF16 + MTP 基线代码、配置、文档和只读监控面板。
2. 固定 benchmark harness 与冻结输入。
3. 运行 200/225/250/275 W 功率实验。
4. 在选定功率点运行并发 2/4/8/16。
5. 运行 FP8 兼容性探针；根据真实 backend 决定是否进入性能比较。
6. 将原始日志、配置身份、汇总指标和排除说明作为独立实验提交，不覆盖本基线。
