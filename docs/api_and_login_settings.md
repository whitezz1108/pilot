# 登录与 API 设置

## 修改网页登录账号或密码

在已经 SSH 登录的服务器终端运行：

```bash
~/pilot01/.venv/bin/python ~/pilot01/deploy/cloud/change_access.py
```

脚本先列出现有账号名，再依次询问：要修改的账号（默认 researcher）、新账号名（回车保持不变）、新密码、再次输入新密码。密码输入时不显示字符，这是正常现象。账号名用2–32位小写字母、数字、下划线或短横线，并以字母开头；密码至少8个字符，可以使用容易记住的较长英文短语，不必堆叠符号。

脚本只更新所选账号，保留另一个账号；重新加载网页登录配置，不重启实验服务。失败时恢复原来的登录配置。服务器的 `~/.pilot01-access.json` 同时更新，电脑上原来的登录信息副本不会自动更新。浏览器若继续使用旧登录，可用无痕窗口重新打开网站。

本次没有替用户选定或更换实际账号密码，由用户在终端输入。

## 网站查看、修改和选择 API

在实验台运行设置区点击“查看 / 修改 API 配置”：查看每个API的完整Base URL、固定实验模型、是否已配置Key，以及Key的短指纹。指纹用于辨认配置，页面不返回现有Key全文。

填写新地址或新Key后点击“保存 API 配置”。Key留空表示保留原值，保存会写入服务器 `config/api.local.env`，不会发起测试请求；页面不支持修改模型。地址填到 `/v1` 等接口根路径，不包含 `/chat/completions`。可以同时保留两个地址相同、Key不同的API。

在实验台点击“API 1”“API 2”“同时使用”，选择本轮实际使用的接口；也可在“API与执行预算”中逐个勾选。选择只有在点击开始后才用于新批次，两个API共用原有总并发上限，不自动加倍。每个run的Manager和Compliance继续固定在同一个slot。

运行中允许查看配置，但不能修改或切换。新批次的账号槽位、地址和Key指纹保存到批次快照；如果中断后相关地址或Key改变，继续旧批次会被拒绝，需恢复原配置或新建一轮。两位网页登录用户共享同一份API配置。
