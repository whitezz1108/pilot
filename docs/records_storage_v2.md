# 实验记录存储与查询 v2

后续分类存储、单轮按需查询与 v3 导出见 [records_storage_v3.md](records_storage_v3.md)。下文为 v2 历史设计。

2026-10-19：修复批次浏览全量读取日志、每run重复解析完整计划、上传包单轮查询解析整包和默认导出大JSON的问题。不改变实验条件、模型输入、工作流、评分规则或原始日志格式。

## 数据边界

`raw/<batch>/<run>/`和冻结的`manifests/`仍保存实验事实。`index/records.sqlite3`是可重建的研究侧查询索引，不进入agent输入。旧批次没有匹配的registry指纹时，不补充当前gold标注。CSV没有原始日志时，不生成回放或恢复率。

SQLite使用WAL、外键、事务和30秒锁等待。连接按请求关闭；同一服务内的索引同步受锁保护。schema版本为`PRAGMA user_version=1`，本次不引入第三方依赖。

| 表 | 主键 | 查询字段与内容 |
| --- | --- | --- |
| `batches` | `id` | 本地/导入来源、来源签名、轻量批次元数据、整批汇总 |
| `runs` | `(batch_id, run_id)` | 序号、合同、条件、E、状态、动作、token、来源签名、导入单轮文件路径、小型摘要 |

`runs`按`(batch_id, ordinal)`唯一约束保持冻结顺序，按批次/状态、批次/条件、批次/E建索引。摘要JSON只容纳可变的展示和核验字段，没有prompt、模型响应或工具返回正文；正文按run保存在文件中。历史中断尝试保持现有原始目录，不把不同尝试的日志合并。

## 读取与更新

1. 首次发现批次：读取一次session和plan，逐run流式扫描日志生成摘要，事务提交索引。不会重写raw、plan或session。
2. 批次列表：复用已保存的批次元数据和汇总。来源签名或活动状态变化时同步。
3. 批次详情：目录元数据检查发现变化的run，只重新读取变化项；SQL筛选、排序、分页，默认100项，上限200项。统计覆盖整批所选项，另保留完整计划分母。
4. 单轮详情：本地只读取该run的文件；导入数据用主键定位单轮文件。单轮内部的完整日志仍一次返回，长文本在页面展开时渲染。
5. 实时状态：复用摘要，不缓存整批prompt。`since`游标返回变化行和移除ID；服务重启、游标过期会返回完整轻量快照。最近8个快照供不同客户端追赶。已完成且未变化的run不再解析日志。
6. 运行中的JSONL只接收以LF结尾的完整行；未写完的尾行等后续刷新。HTTP尝试统计保留读取偏移和计数，不积累完整日志。

本地修改原始文件后，刷新批次详情会重算变化项。重新打开服务无需重建未变化的run。首次建立索引和首次拆分旧包仍需要读取原数据；这部分一次性成本不会被伪装为正常分页延迟。

## 导入与导出

默认`GET /api/records/export?id=...`返回分轮ZIP，服务端临时文件打包、分块发送；内存占用随单轮记录大小变化。`format=json`仅保留旧客户端兼容接口，仍会组装整批JSON，不用于日常浏览和默认导出。

ZIP格式为`pilot01-records-zip-v2`：根`manifest.json`包含batch和entries，`runs/000000/record.json`等文件各保存一轮的完整旧record结构。它是可回放记录包，不是替代部署备份的原始目录镜像；完整源文件备份继续使用云端备份脚本。

新上传记录以`pilot01-records-split-v2`清单和每run独立文件保存。文件名由系统序号生成，不使用上传run_id拼接路径。旧`bundle.json`首次访问时拆分，但保留原件。CSV、旧JSON及原始日志ZIP继续兼容。ZIP路径、重复文件、run_id一致性、数量和展开大小会校验；失败导入不发布半成品。

限制：ZIP压缩文件512MiB、展开2GiB，最多100000个文件/10000轮，单轮128MiB；CSV/旧JSON64MiB。浏览器、后端和云网关限制相配。大于限制的批次需要分包；完整ZIP导出本身不受上传上限限制，因此超限导出不能直接整包重新上传。

## 维护与重建

本地Windows PowerShell：

```powershell
.venv/Scripts/python.exe scripts/rebuild_records_index.py
```

服务器SSH/Linux：

```bash
cd ~/pilot01
PYTHONPATH=src .venv/bin/python scripts/rebuild_records_index.py
```

默认检查并增量同步全部批次；`--rebuild`只清除并重建派生数据库行，保留原始记录和上传原件。首次建立索引可在服务开放前运行。脚本不加载API凭证、不构造模型客户端。

备份脚本排除可重建的`index/`，避免把正在使用的SQLite/WAL文件按普通文件复制。恢复原始数据后自动重建索引。源码升级需等待当前实验结束并重启服务；不要绕过既有实验版本冻结检查。云端更新脚本会保留原TLS/账号配置并将网关上传上限同步到512MiB。
