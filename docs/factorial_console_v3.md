# 可手动选择 A / V / E / D 的实验台

本版入口为 `config/experiment_v3.yaml`，使用 `conditions_v3.yaml`、`runtime_v3.yaml` 和 `manager_v5` / `compliance_v5`。保留原 D-only 配置、prompt 与历史数据；本版新批次有独立 ID 和代码指纹，不能继续混入旧批次。

## 四个因素

| 因素 | 取值 | 实际执行 |
|---|---|---|
| A：原文权限 | A0 / A1 | A0 不提供原文工具，调用也不能获得原文；A1 允许搜索和打开合同段落。 |
| V：查证任务 | V0 / V1 | V0 由节点自行决定是否查证；V1 在任务中明确要求分别检索政策目标并打开相关证据。 |
| E：输入memo | E0 / E1 | E0 使用完整冻结memo；E1 使用目标claim替换成中性背景claim的冻结memo。 |
| D：检查告知 | D0 / D1 / D2 | 不明确告知检查 / 告知会检查 / 告知会检查及完整细则；两节点使用同一D。 |

用户于2026-10-18确认：V1不表示程序拦截。所有组合均运行相同程序检查，只记录检查结果，不反馈、不重做、不因检查失败终止。结构不可解析、工具预算耗尽和传输异常等执行失败仍保留。D0不代表节点不知道自己的查证任务：V1任务要求和D检查告知是两个独立维度。

A0V1因无原文权限而无法完成查证，被禁用；不在每份合同下创建任何A0V1D0/D1/D2运行。A0下与查原文有关的检查项可能结构性不通过，不能直接解释为组织或模型错误，也不等于执行失败。

## 材料与轮次

新旧各40份合同都在同一个已冻结的80份数据集中。原先入口只选择旧40份，本版提供旧40、新40、全部80三个范围。每组40份均有40份E0与32份E1；8个负例只有E0。全80份合计80个E0＋64个E1＝144份memo，不创造负例E1。

总run数＝所选范围内实际存在的E材料数 × 有效A/V/D组合数 × 每格重复次数。

| 示例 | 每格重复1次 | 每格重复3次 |
|---|---:|---:|
| 全80份＋E0/E1＋全部有效A/V/D | 1296 | 3888 |
| 旧40份或新40份＋E0/E1＋全部有效A/V/D | 648 | 1944 |
| 全80份＋仅E0＋全部有效A/V/D | 720 | 2160 |
| 全80份＋仅E1＋全部有效A/V/D | 576 | 1728 |

选择条件时自动计算总数，生成清单后可运行完整计划或只勾选部分run。完整计划分母与实际选择数量分别保存。部分任意筛选不保证配对，也不自动构成正式研究设计。旧40与新40仍分别标记，不混淆开发材料与独立材料的研究用途。

### 按组选择本轮范围

配置区横向分为材料、条件、完整计划；下方设置本轮范围与并发数。API和预算折叠显示。

“每组N轮”将固定随机顺序的清单切成互不重叠的连续组；滑块、首组/末组和左右按钮选择其中一组。例如1296项、每组64轮：首组1–64，第二组65–128，第21组1281–1296（16轮）。改变每组数量后从首组重新选择。“全部”选择完整清单。

移动滑块会替换当前勾选，并切到待启动清单对应页。手动勾选后显示“手动选择”，保留每组大小；再次移动滑块恢复整组选取。页面分别显示A/V/E/D实际选中数量；连续组不保证配对或均衡。新一轮不自动跳过历史run；只有点击开始才调用API。实际选择ID仍按原方式保存到launch_selection.json，实验排序、预算和agent行为不变。

## 在线材料预览

`/materials` 支持按新旧范围与中性CASE编号筛选，可查看E0/E1各5条claim、claim实际引用的原文段落和完整合同。只有E0的合同禁用E1切换。内容直接读取冻结registry，不生成、不改写memo；显示原文SHA256。预览属于研究者页面，不扩大任何agent的输入和工具权限，不调用模型。

## 冻结与恢复

`run_plan.json` 冻结实际A/V/D条件、E选择、合同集合、重复次数、runtime、模型参数及profile指纹；`console_session.json` 和 `launch_selection.json` 保存用户因子选择。CSV分列导出A、V、D、memo。

每节点仍最多16次工具请求，单次输出最多32768 tokens；服务端默认并发16，可手动调整。新版启动不自动补跑历史中断项。历史记录保持原字节，恢复执行要求同一profile，代码变化后应生成新批次。
