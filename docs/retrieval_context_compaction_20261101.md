# 检索上下文压缩与无新增停止规则（2026-11-01）

## 版本边界

新入口为`config/experiment_native_tools_context_compact_v2.yaml`。旧的32768-token配置、context-safe v1配置及其批次均不改写。该变化同时影响模型可见检索历史和搜索停止行为，因此新旧批次不能只按结果字段直接合并。

## 两份历史

实验审计历史保持完整：每次模型请求、工具调用、查询、游标、候选ID、摘录、完整段落、错误和时间戳继续写入原有JSONL记录。

模型工作上下文允许压缩：删除时以完整的assistant native tool call与对应tool result为单位，绝不留下孤立tool消息。压缩项由确定性运行时生成`RUNTIME RETRIEVAL LEDGER`，至少保留工具序号、查询、target category、错误或无新增状态，以及仍属于当前合同的候选段落ID。

## 压缩规则

1. 搜索或翻页没有返回新段落ID时，下一轮直接使用短账本，不重复放入长工具结果。
2. 输入估计超过18000 tokens时，依时间顺序压缩模型已经看过的旧搜索，直到不高于12000 tokens或没有可压缩项。
3. `open_source_span`返回的完整段落永不压缩，保证最终判断仍能读取逐字证据。
4. 搜索返回的新候选尚未至少完整展示一次前，不因token压力压缩。
5. 压缩只改变后续模型请求；append-only模型日志、工具日志和证据账本不删除、不摘要。

## 防循环规则

- 查询以小写词序列和target category规范化；完全相同的规范化查询由工具层拒绝。
- 拒绝仍是一条真实工具结果，消耗一次16次共享预算并进入日志。
- 连续3次搜索或翻页没有新增段落ID后，搜索和翻页schema从后续请求中移除。
- 已由搜索返回的合法段落仍可通过`open_source_span`打开；如果没有足够证据，模型应提交`unknown`，而不是继续近似搜索。

该规则不使用gold、目标答案或语义模型判断“搜索是否有效”。唯一判据是工具运行时可观察的新增段落ID，因此不会针对某个失败案例调整相关性结论。
